|---|---|
| 驱动版本 | NullMoth NVIDIA Driver **2.4.3** |
| 加载的 kext | NVRM / NVAccel / NVRMFB / NVRMAGDC（四个全部 2.4.3） |

| Metal | Metal 3 |
| VRAM | 6144 MB |
| BAR | BAR1 = 8192 MB |

### 关键 boot-args

```
debug=0x100 keepsyms=1 -vi2c-force-polling -ibtcompatbeta
revpatch=sbvmm,cpuname nvfb=1 nvaccel=1 nvfbheads=4
-nvkmsnosmooth amfi_get_out_of_my_way=0x1 amfi=0x80
ipc_control_port_options=0 gfxrst=4 nvrmacpibl=1 -v
alcid=21 revcpu=1
```

说明：
- `revpatch=...cpuname` + `revcpu=1`：让「关于本机」正确显示 i7-11800H，而不是机型模板里的 Xeon
- `alcid=21`：声卡 layout（见第五节）
- `-v`：verbose 启动（想关掉就删掉这个参数）

### 回滚点

```
最新（2.4.3 安装前）：`/Library/NullMoth/backup-20261020-131016.NuLh9c`
更早（2.3.7 安装前）：`/Library/NullMoth/backup-20261020-024949.stIYKs`

```bash
sudo ./uninstall.sh <上面的目录>     # 回退驱动
```
```

OpenCore 菜单里还有两个应急项：
- `1401: Remove NVIDIA driver`
- `1401: Start once without NVIDIA driver`

## 五、音频

| 项目 | 内容 |
|---|---|
| 声卡 | Realtek ALC295 / ALC3254（Codec ID 0x10ec0295） |
| 当前驱动 | **VoodooHDA 3.7.0** + `voodoo-layout-id = 21` |
| 备用驱动 | AppleALC 1.9.7 + SimpleHDA 1.0.0（保留在 EFI 里，`Enabled=false`） |
| 设备 | `Internal Speakers` / `Internal Microphone` |

### 为什么最终选了 VoodooHDA

macOS Tahoe 从 beta 2 起**删除了 AppleHDA.kext**，需要用 SimpleHDA 这类方案补回音效栈。
但实测 **SimpleHDA 方案在睡眠唤醒后必然失声**，而且 `killall coreaudiod` 救不回来
（`CodecCommander` 在 macOS 12.3+ 已失效，`alc-verb` 也连不上它的 provider）。

换成 **VoodooHDA 3.7.0** 后，睡眠 / 手动睡眠唤醒后声音都正常，麦克风也在。

### 关键配置

1. kext：`VoodooHDA.kext`（来源 `CloverHackyColor/VoodooHDA` 的 v3.7.0 release）
2. ⚠️ **`ExecutablePath` 必须写 `Contents/MacOS/VoodooHDA_BL`**（它的二进制叫 `VoodooHDA_BL`，
   写成 `VoodooHDA` 会导致 OpenCore 开机直接 `Halting on critical error`）
3. `DeviceProperties → Add → PciRoot(0x0)/Pci(0x1f,0x3) → voodoo-layout-id = <15 00 00 00>`（即 21）
   - 不设这一项：只有输出设备、**麦克风消失**，而且默认输出会选成 Headphones（听起来像"没声音"）
   - 设了之后：设备变名为 `Internal Speakers` / `Internal Microphone`，一切正常
4. AppleALC 与 SimpleHDA 的条目设为 `Enabled=false`（保留以便回滚）

### 常见问题：突然没声音

1. **先看默认输出设备对不对**（系统设置 → 声音 → 输出）
2. 还不行 → 重启一次
3. 想回滚到 SimpleHDA：把 AppleALC / SimpleHDA 的 `Enabled` 改回 `true`，VoodooHDA 设 `false`

排查命令：
```bash
system_profiler SPAudioDataType | grep -E "Internal|Default Output"
osascript -e "get volume settings"    # input volume 不应是 missing value
```

## 七、触控板（重点配置）

| 项目 | 内容 |
|---|---|
| 硬件 | I2C-HID 触控板，ACPI 路径 `I2C1@150001` → `TPD0` |
| 驱动 | VoodooI2C 2.9.1 + VoodooI2CHID + VoodooGPIO + VoodooInput |
| 状态 | 精密触控板，**全部多指手势可用** |

### 关键配置：I2C 控制器 device-id 伪装

VoodooI2C 的 PCI 匹配表**不包含 Tiger Lake-H 的 `43e8`**，必须把 I2C1 控制器伪装成 Ice Lake 的 `34e8`：

```
DeviceProperties → Add → PciRoot(0x0)/Pci(0x15,0x1)
    device-id = <e8 34 00 00>      ← 必须是 4 字节 Data，不能是字符串！
```

**这是本次调试最大的坑**：用 `PlistBuddy -c "Add ... data E8340000"` 会写成 **8 字节 ASCII 字符串**，OpenCore 静默忽略，表现为「改了但完全没效果」。

正确改法：
```bash
sudo plutil -convert xml1 config.plist
# 把对应 <data> 内容替换为 6DQAAA==（即 e8 34 00 00）
sudo plutil -lint config.plist
```

验证：
```bash
plutil -p config.plist | grep -A2 "Pci(0x15,0x1)"
# 应显示：device-id => {length = 4, bytes = 0xe8340000}

ioreg -p IODeviceTree -n I2C1 -r -l -w0 | grep device-id
# 应显示：<e8340000>
```

## 八、性能实测（2026-10-20）

### CPU（Geekbench 7）

| 项目 | 本机 | i7-11800H 平均 | 对比 |
|---|---|---|---|
| 单核 | **1723** | 1687 | +2.1% |
| 多核 | **8559** | 8087 | +5.8% |

频率与功耗（powermetrics 实测）：

- 空闲：1,070 MHz（自动降频）
- 8 线程满载：**4,198 MHz**（全核睿频拉满，无降频）

**结论：CPU 侧与原生系统无差别，甚至略优于平均。**

### GPU（RTX 3060 Laptop）

| 测试 | 结果 |
|---|---|
| Geekbench Metal compute | **挂死**（0% CPU，无响应，无内核报错） |
| Geekbench OpenCL compute | **挂死** |
| 1080p H.264 → 720p 转码（23 秒素材） | 23.3 秒 / 124% CPU → **软件编码** |
| 4K HEVC DV → 1080p HEVC | 41.5 秒 / 226% CPU → 软件编码 |

驱动里**带了**硬件编解码库（`libnvenc_*_ga10x.dylib`、`libnvdec_*.dylib`），转码时进程也确实加载了它们，
但 **VideoToolbox 没有把任务路由过去** —— 对应上游 issue #175 / #275，尚未修复。

**结论：这台机器在 macOS 下只能当"显示卡"用；GPU 计算/编解码一律走 CPU，要算力回 Windows。**

### ⚠️ 有瑕疵

| 问题 | 原因 | 应对 |
|---|---|---|
| 4K HEVC 视频卡顿 | 视频解码走 CPU 软解（NVDEC 未接上） | 看 1080p，或换播放器试 |
| 温度/风扇读不到 | VirtualSMC 不暴露 SMC 温度键 | 无解，硬件限制 |
| 偶发后台进程吃 CPU | iCloud 同步（cloudd / fileproviderd） | 关掉不需要的 iCloud 同步 |

### ❌ 不可用（硬件限制）

| 功能 | 原因 | 解决 |
|---|---|---|
| 隔空投送 / 接力 / 通用剪贴板 | Intel 网卡不支持 AWDL | 换博通 BCM94360NG 网卡 |
| Force Touch 压力触控 | 触控板没有压力传感器 | 无解 |
| Intel 核显加速 / QSV | 11 代核显 macOS 无驱动 | 无解（但用独显直连不影响显示） |
| 电池健康 | 循环 565 次，判定「建议维修」 | 换电池 |

### ❓ 未验证

- HDMI 外接显示器
- 3.5mm 耳机孔（插入自动切换）
- 雷电/USB-C 口
- 4 个 USB-A 口是否都能正常使用

## 十、更新策略（重要）

### macOS 系统更新

**原则：默认不升，要升先查驱动支持情况。**

1. 自动更新已关闭，保持关闭
2. 小版本（26.7.x）可能安全，但可能打破驱动，升级前先备份 EFI
3. **macOS 27 不再支持 Intel，绝对不要尝试**
4. 升级后立刻检查：`kmutil showloaded --list-only | grep nullmoth`，应有 4 行

### NullMoth 驱动更新

1. 打开 `1401` app，会检测新版本并提供 Update
2. 或者手动下载 `nullmoth-nvidia-X.X.X.tar.gz`
3. 解包后 `cd pkgroot && shasum -a 256 -c SHA256SUMS && sudo ./install.sh`
4. 重启，必要时在「隐私与安全性」允许扩展后再重启一次

**注意**：升级前先看 GitHub Releases 的说明，不要只看版本号大小。

### 其它 kext 更新

OpenCore 的 kext 是启动时注入，替换 `EFI/OC/Kexts/` 里的目录再重启即可：

1. **目录名不能改**（`Kernel → Add` 里靠 BundlePath 匹配）
2. 替换前备份整个 EFI
3. 保持原注入顺序（Lilu 最前，父 kext 在插件前）

### 备份制度

每次改配置前：
```bash
sudo diskutil mount disk1s1
sudo cp -R /Volumes/EFI/EFI ~/EFI-backup-$(date +%m%d)
```

## 十三、安装过程中踩过的坑（备查）

1. **恢复模式下磁盘编号会变**：Recovery 里 512G 是 disk0，进 macOS 后变成 disk1，按容量认盘不要按编号
2. **16G U 盘只能做 Recovery 盘**：Tahoe 安装包 18.4GB，需在线下载；断流会报 `PKDownloadError 8/14`，重试可续传
3. **AppleHDA 在 Tahoe 已被删除**：需要 SimpleHDA 补回（详见第五节）
4. **VoodooI2C 缺 Tiger Lake 支持**：必须做 device-id 伪装，且**必须是 4 字节 Data**
5. **NullMoth 2.3.6 图标渲染 bug**：升级 2.3.7 修复
6. **动态壁纸极耗性能**：4K 航拍视频壁纸会让 WindowServer 飙到 150%+，换静态壁纸
7. **iCloud 照片同步吃满 CPU**：新装系统会后台同步，建议关掉
